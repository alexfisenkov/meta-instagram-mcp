# Подключить Instagram: сначала выбрать простой путь

У MCP есть два основных способа работы: **официальный API** и **свой браузер Chrome**. Сначала проверьте возможность прямого Instagram Login. Если этот setup недоступен или настройка Meta упирается в бизнес-доступы, можно выбрать браузер. Unified Login и прежний Facebook Login остаются отдельными вариантами.

## Порядок для агента

1. Определите ОС, MCP-клиент, установленную версию и используемый приватный конфиг. Рабочее подключение сначала проверьте безопасным чтением, сохраните его настройки. Обновление программы не требует переводить существующий аккаунт в другой login mode.
2. Вызовите **`meta_connection_plan`** с `{}`. Этот инструмент не входит в Meta, не меняет конфиг и не создаёт portfolio. Он показывает пути и следующий шаг. Версия `v0.3.0` этого инструмента ещё не содержит — сначала обновитесь по [инструкции](install.md#обновить-откатить-или-удалить).
3. В реальном Meta App Dashboard осмотрите раздел Instagram: есть ли **API setup with Instagram login** / **Instagram business login**, его собственные Instagram App ID/Secret и генерация Instagram User token. Это отдельный setup от Unified. Не считайте наличие Unified доказательством отсутствия direct setup. Если доступ не осмотрен, оставьте статус `unknown`.
4. Передайте наблюдение в planner, например `{"directInstagramSetup":"available"}`. Его данные помечены `caller_supplied`: инструмент не проверял ваш Dashboard и не подтверждает права Meta. Если уже проверенное подключение работает, передайте `existingConnectionWorking:true`; при доказанном отказе — `false`, чтобы не повторять проверку по кругу.
5. Выберите подходящую инструкцию ниже. Не запрашивайте пароли, токены, App Secret и callback code в чате. Пользователь вводит секреты локально и проходит личный вход сам.
6. Готовность подтвердите чтением ожидаемого аккаунта и нужной операции. Установленный пакет, наличие ключей, state URL, heartbeat и список capabilities по отдельности этого не доказывают. Если planner сообщил `token_store_occupied_by_other_credential`, сначала сохраните старое хранилище и выберите отдельный приватный state для нового токена; не повторяйте импорт в занятый файл.

| Путь | Когда выбирать | Что нужно | Инструкция |
|---|---|---|---|
| Прямой Instagram Login | Подходящий setup действительно доступен; нужны разрешённые API данные | Профессиональный Instagram и собственная App с этим setup | [Прямой официальный вход](direct-instagram-login.md) |
| Браузер Chrome | Не хочется проходить Meta App setup либо он заблокирован; достаточно видимого интерфейса | Свой вход и существующий browser-инструмент AI-клиента; при необходимости — наш local companion | [Браузер без Meta App](browser-only.md) |
| Unified Login | Direct setup недоступен, выбран соответствующий setup и есть права на portfolio | Meta App, доступное business portfolio, BISU; для MCP OAuth — HTTPS callback | [Unified](unified-login.md) |
| Прежний Facebook Login | Уже есть подходящее работающее подключение | Его собственные выданные права и привязки | [Meta setup](meta-setup.md) |

Прямой Instagram Login и Unified используют разные credentials, token family, scopes и Graph host. Переключение одной переменной не превращает токен одного режима в другой. При выборе нового режима сохраните старый config/token-store и используйте отдельный приватный каталог.

## Если Meta отказала в business-доступе

`User Cannot be Added to Business` или техническая ошибка назначения App к portfolio не означают, что надо переустановить MCP или писать новый адаптер. Остановите повторные приглашения, переносы приложения и создание portfolio. Проверьте direct setup и предложите Chrome-путь. Причину административного отказа выясняйте по конкретному экрану Meta и роли владельца; не угадывайте блокировку/бан/верификацию по одной фразе.

Пример после осмотра:

```json
{
  "directInstagramSetup": "unavailable",
  "unifiedSetup": "available",
  "businessPortfolio": "blocked"
}
```

Planner предложит браузер. Сначала проверьте уже имеющийся browser control AI-клиента: `existingBrowserControl:available|unavailable|unknown`. При доступном инструменте можно читать свой Chrome без дополнительной установки. Если нужен именно наш MCP browser source, используйте локальный companion. Это рекомендация маршрута, не подтверждение подключения. Если пользователь сразу выбрал браузер, вызовите `{"preferredSource":"browser"}` и переходите к его инструкции без Meta App.

## Как явно выбрать источник чтения

Для browser-проверки используйте:

```json
{"source":"browser","operation":"account.inspect"}
```

Это аргументы `meta_read_source`. Откройте свой профиль в единственной Instagram-вкладке. После проверки владельца `data.profile` содержит только поддержанные видимые сведения и ссылки, с пометками ограниченного покрытия. Для Direct/comments используйте соответствующую операцию и точный target из свежего наблюдения. Открытие диалога может пометить сообщения просмотренными.

`source:"browser"` не обращается к API и не переключается на другой источник при ошибке. `source:"api"` и `source:"phone"` также выбирают один источник. Без `source` или с `source:"auto"` сохраняется ограниченный fallback API → browser → phone. Выбор источника чтения не включает запись.

## Откуда требования

Meta сравнивает login setups в [официальной таблице](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login): прямой Instagram Login не требует business portfolio, Unified требует. Фактическая доступность setup в конкретной App проверяется отдельно. [Direct Get Started](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/get-started) описывает Dashboard token и первый profile/media read. Проверено по первоисточникам 16.11.2026.
