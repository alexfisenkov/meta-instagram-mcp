# Instagram через свой Chrome, без Meta App

Этот путь использует ваш обычный вход в Instagram в Google Chrome. Создавать
Meta App, бизнес-портфолио, VPS, домен или HTTPS-сертификат не требуется.
Для чтения через уже подключённый browser-инструмент действуют требования самого AI-клиента. Для нашего локального MCP companion нужны Chrome, Node.js 22+ и установленный MCP из этого релиза.
Вы входите в Instagram и подтверждаете проверки безопасности самостоятельно.

## Сначала проверьте уже подключённый браузер

Если ваш AI-клиент уже умеет управлять вашим обычным Chrome, начните с этого инструмента: подтвердите нужный профиль, личный вход и прочитайте видимую страницу. Не ставьте ещё одно расширение только потому, что оно есть в репозитории. В `meta_connection_plan` передайте `preferredSource:"browser"` и наблюдение `existingBrowserControl:"available"`; если доступ не проверен — оставьте `unknown`.

Работа такого браузерного инструмента клиента — самостоятельный путь. Она не означает, что подключён наш MCP browser source. Следующие шаги нужны, если у клиента нет подходящего browser control или вы осознанно хотите получать наблюдения через `meta_read_source(source:"browser")` нашего MCP.

## Что доступно

Browser companion проверяет выбранный Instagram-профиль и читает поддержанные
видимые страницы через фиксированные операции. В текущем контракте есть
`account.inspect`, `inbox.list`, `conversation.read`,
`comments.list` и `comments.replies`. Готовность каждой операции проверяется
отдельно; список в настройке не доказывает, что текущая разметка Instagram
поддерживается. Если интерфейс изменился или профиль нельзя подтвердить,
возвращается `needs_selection` либо `unsupported_ui_version`.

Это ограниченный браузерный источник. Он не выдаёт полный архив, все страницы
переписки или полную статистику Insights. Чтение открытого диалога может
пометить сообщения просмотренными. Настройщик оставляет браузерные записи
выключенными; публикации, реакции и отправка сообщений этим сценарием не
включаются.

Внутренний `account.snapshot` — alias extension, а публичный MCP принимает `account.inspect`. На точной странице своего профиля этот read дополнительно возвращает ограниченный видимый header и ссылки на видимые публикации/Reels, с пометкой partial/visible-only. Если открыта другая страница, профильный снимок требует открыть свой профиль. Ссылки сами по себе не подтверждают авторство публикации.

## 1. Подготовить Chrome

1. В своём обычном профиле Chrome войдите в Instagram. Оставьте одну вкладку
   Instagram с нужным аккаунтом. Пароль, cookies и код подтверждения в чат
   агенту не передавайте.
2. Откройте `chrome://extensions`, включите режим разработчика и нажмите
   «Загрузить распакованное расширение».
3. Выберите папку `browser-extension` внутри постоянной установленной папки
   MCP, например `~/.local/share/meta-instagram-mcp/app/browser-extension`.
4. Скопируйте ID установленного расширения: это 32 символа от `a` до `p`.
   Случайный ID из примера не подойдёт. Расширение загружается из вашего
   установленного пакета и работает только с разрешёнными Instagram-страницами.

Если MCP ещё не установлен, сначала выполните [установку](install.md).
Обновление установленных файлов требует перезагрузки расширения в Chrome.

## 2. Проверить план настройки

Откройте терминал в установленной папке MCP. Вместо значений в угловых скобках
укажите свой ID расширения и Instagram username без `@`:

```sh
node tools/cli.mjs browser-setup --extension-id '<ID-РАСШИРЕНИЯ>' --account-handle '<USERNAME>'
```

По умолчанию это **dry-run**: команда проверяет пути, конфликты настройки и
регистрацию Native Messaging Host, затем показывает план. Она не записывает
файлы, не регистрирует host и не входит в Instagram.

Для нестандартной установки укажите абсолютные пути через `--install-root`
и `--config-dir`. Если выбран `--config-dir`, обязательно задайте **тот же абсолютный каталог** в `META_MCP_CONFIG_DIR` окружения записи MCP вашего AI-клиента (например, `env = { META_MCP_CONFIG_DIR = "/absolute/private/config" }` в Codex TOML или `"env": { "META_MCP_CONFIG_DIR": "/absolute/private/config" }` в JSON). Не помещайте этот ключ внутрь `.env`: runtime выбирает каталог до чтения файла. Примеры полной записи — [изоляция конфигурации](unified-login.md#сохранить-прежнее-подключение-отдельно).

Порт по умолчанию — `8788`; другой свободный порт задаётся
через `--port`. Если нужный порт уже задан в приватном конфиге, используется он.

На Windows сначала нужен шаг ниже; затем эта же команда получает ещё
`--windows-exe-sha256 '<SHA256>'`.

## Windows: готовый Native Host

Откройте [Assets опубликованного релиза](https://github.com/alexfisenkov/meta-instagram-mcp/releases/latest).
Скачайте `InstagramNativeHost.exe`, `InstagramNativeHost.exe.sha256` и
`InstagramNativeHost.exe.provenance.txt` из одного проверенного релиза.
Поместите exe в `tools/native-host/InstagramNativeHost.exe` установленной
папки MCP. Создайте папку `tools/native-host`, если её ещё нет.

Сверьте SHA-256 файла с опубликованным `.sha256`; для самостоятельной проверки
в PowerShell подходит `Get-FileHash -Algorithm SHA256`. Передайте ожидаемые
64 шестнадцатеричных символа из `.sha256` настройщику:

```powershell
node tools/cli.mjs browser-setup --extension-id '<ID-РАСШИРЕНИЯ>' --account-handle '<USERNAME>' --windows-exe-sha256 '<SHA256>'
```

Настройщик ещё раз вычисляет SHA-256 установленного exe и отказывает при
несовпадении. Он ничего не скачивает и не просит устанавливать .NET SDK или
собирать launcher самостоятельно. Если в выбранном релизе нет готового exe
или контрольной суммы, этот путь Windows ещё не подготовлен для установки.
Файл provenance фиксирует происхождение артефакта; сама контрольная сумма не
заменяет проверку источника загрузки.

## 3. Применить план

Повторите ту же команду, добавив `--apply`:

```sh
node tools/cli.mjs browser-setup --extension-id '<ID-РАСШИРЕНИЯ>' --account-handle '<USERNAME>' --apply
```

На Windows сохраните также аргумент `--windows-exe-sha256`.

Команда создаёт приватный `browser-bridge.json`, случайный bearer и привязку к
выбранному username, дополняет внешний `.env` и регистрирует host только для
точного ID расширения. Перед дополнением существующего `.env` сохраняется
его приватная копия `.env.backup-*`. Meta-токены и прочие MCP-клиенты не
меняются; bearer и credentials не печатаются в результате.

В macOS/Linux bridge JSON находится рядом с внешним `.env`. На Windows
launcher использует `%LOCALAPPDATA%/MetaInstagramCompanion/browser-bridge.json`.
Повторная настройка с теми же параметрами сохраняет уже выданные bridge
credentials и не добавляет повторяющиеся строки `.env`.

Чужой manifest/launcher, несовместимые настройки HTTP, удалённый proxy или
неизвестный bridge JSON означают отказ до изменения конфигурации. Настройщик
не заменяет их автоматически. При смене аккаунта, ID расширения или
постоянного install root сначала требуется отдельная осознанная миграция.

## 4. Перезапустить и проверить

1. Проверьте, что запись AI-клиента читает именно каталог из плана настройки; при custom path нужен `META_MCP_CONFIG_DIR` в окружении клиента. Полностью перезапустите MCP-подключение в своём AI-клиенте.
2. Перезагрузите расширение в `chrome://extensions`; вкладка Instagram должна
   оставаться открытой и авторизованной в ожидаемом аккаунте.
3. Попросите агента проверить `meta_capabilities`, затем выполнить
   `meta_read_source` с `source: "browser"` и `operation: "account.inspect"`.
4. Успех — подтверждённый ожидаемый username и доступный безопасный read
   выбранной операции. Один статус установки или `HTTP /health` этого не
   доказывает.

`node tools/doctor.mjs` проверяет запуск MCP и общую доступность источников.
Он не выполняет личный вход и не подтверждает чтение нужного экрана.

## Как это устроено

`INSTAGRAM_MCP_BROWSER_BRIDGE=true` добавляет к обычному stdio-MCP приватный
HTTP listener на `127.0.0.1` **в том же процессе и с тем же Hub**. Отдельный
сервер не запускается. Native Host обращается к этому listener со случайным
bearer. В этом local-only режиме доступны только health и browser bridge routes: `/mcp`, OAuth/webhook и phone routes через этот порт закрыты. Ранее включённые API write flags не получают новый HTTP доступ через браузерный bearer. При закрытии stdio или завершении процесса listener закрывается.

HTTP разрешается browser bridge только при явном `allowLoopbackHttp: true`
и буквальном локальном адресе `127.0.0.1` либо `[::1]`. Настройщик использует
`127.0.0.1`. `localhost`, другие адреса `127.*`, DNS-имена и удалённый HTTP
отклоняются. Redirect не выполняется, поэтому bearer не пересылается на
другой адрес. Для удалённых Hub остаётся прежнее требование HTTPS.

## Если не подключается

- `BROWSER_BRIDGE_TRANSPORT_CONFLICT` / `BROWSER_BRIDGE_REMOTE_CONFLICT`: в окружении записи MCP-клиента включён полный HTTP transport или удалённый proxy одновременно с local browser profile. Runtime отказывается запускать такой смешанный профиль. Приведите окружение клиента к тому же локальному stdio-плану; настройки одного `.env` не отменяют client environment.
- `BROWSER_SETUP_CONFIG_CONFLICT`: существующий конфиг задаёт другой transport,
  remote proxy, host/порт или bridge settings. Сначала разберите конфликт;
  повторные `--apply` его не устранят.
- `EXISTING_REGISTRATION_CONFLICT` / `EXISTING_LAUNCHER_CONFLICT`: найден чужой
  либо независимо изменённый Native Host. Содержимое сохраняется; автоматического
  перезаписывания нет.
- `WINDOWS_HOST_MISSING` / `WINDOWS_HOST_CHECKSUM_*`: проверьте файл exe и
  контрольную сумму из опубликованного релиза.
- `REGISTRY_READ_FAILED` / `REGISTRY_WRITE_FAILED`: системный Windows reader не смог достоверно прочитать регистрацию либо запись отказала. Настройка останавливается, чужой ключ не считается пустым. Проверьте доступность встроенного PowerShell и права текущего пользователя; не удаляйте чужую регистрацию.
- `BROWSER_SETUP_LOCKED`: работает другая настройка либо остался её lock после
  аварии. Не удаляйте его наугад; проверьте, завершился ли прежний процесс.
- `not_connected`: проверьте ID расширения, регистрацию host и перезагрузку
  расширения после настройки. Если Node.js установили, пока Chrome уже работал,
  полностью перезапустите Chrome, чтобы он получил обновлённый PATH.
- `offline`: MCP-клиент должен работать; после его закрытия локальный Hub
  специально недоступен. Проверьте, что выбранный порт не занят.
- `needs_selection`: оставьте одну Instagram-вкладку нужного профиля, проверьте
  username в настройке и повторите только read-проверку.
- Instagram просит подтверждение на знакомом устройстве: подтвердите его
  самостоятельно в обычном браузере/приложении. MCP не обходит эту проверку.

Если применение прервалось после создания приватных файлов, сначала сохраните
их и разберите сообщение об ошибке. Настройка не удаляет подготовленный bridge
при сбое регистрации; после устранения причины повтор с теми же параметрами
использует его. Исходный `.env` хранится в приватном backup, если дополнение
уже было выполнено.
