# Публикация видео через student broker

Контур добавляет Instagram Reels, YouTube video, TikTok Direct Post и Pinterest video Pin. Код и синтетические проверки не подтверждают живой допуск приложения, OAuth пользователя или публикацию. YouTube сам классифицирует Shorts. Реальные публикации выполняются только из сохранённого подтверждённого намерения платформы.

## Включение и совместимость

Без `META_BROKER_PUBLISHING_MEDIA_ORIGIN` и `META_BROKER_PUBLISHING_MEDIA_PATH` новый контур выключен: прежние MCP catalog/capabilities, Meta vault и YouTube read-only endpoint сохраняют прежний контракт. При включении origin обязателен точный HTTPS origin, path — точный префикс `/api/v1/social/publishing/media/`. После префикса допускается только один непрозрачный сегмент. Другие origin, query, redirects и произвольные HTTP назначения отвергаются. Значения origin/path оператор берёт из настройки API; конфигурация не является разрешением публиковать.

`META_BROKER_PUBLISHING_CONFIG_FILE` указывает на отдельный приватный JSON с `version:1,products:[]`; пример — `student-publishing.config.example.json`. В каждой записи `product` равен `youtube`, `tiktok` либо `pinterest`, `clientIdEnv`/`clientSecretEnv` содержат имена переменных окружения, `admission` — `disabled`, `test` либо `live`, `testSubjects` — список допущенных субъектов. Отсутствующая пара credentials даёт `not_configured`, частичная пара — отказ запуска. Для Instagram используется существующий subject-bound grant с проверенными scopes и admission; owner token и companions не используются.

Callback paths: `/social/oauth/{youtube|tiktok|pinterest}/callback` на origin `META_BROKER_CALLBACK_URL`. Возврат — `/social` на platform origin. Обратный прокси должен направлять эти точные пути в student broker и исключать OAuth query и media leases из access/error logs. OAuth state одноразовый, живёт 10 минут, закрепляет subject, product, config fingerprint и, при upgrade, ожидаемый стабильный ресурс. Для Google проверяется issuer и PKCE S256. Список разрешённых auth URL формируется только сервером.

Запрошенные scopes:

- YouTube: `openid profile youtube.readonly youtube.upload` (Google scopes с полным официальным URI). Write consent — отдельный flow. Старое чтение допускает дополнительный `youtube.upload` в ответе обмена/refresh того же клиента; отдельный клиент не требуется кодом. Отмена нового flow не меняет read vault.
- TikTok: `user.info.basic,video.publish`. Идентичность — `open_id` из token и `/user/info`.
- Pinterest: `user_accounts:read,boards:read,pins:read,pins:write`. Идентичность — числовая строка `Account.id` из `/user_account`, никогда username.

Подтверждённый identity/read grant сохраняется при отказе в необязательном write scope. `canPublish` и capability `publish` зависят от фактических scopes. YouTube ресурсы объединяются по subject/product/native channel ID; `connectionId` существующего ресурса сохраняется. Upgrade с `connectionId` отвергает другой канал. Disconnect write grant сохраняет read grant и соседние каналы. Внешний revoke этой командой не выполняется и обозначается `not_attempted`.

## Хранение и выполнение

Подкаталог `publishing/` внутри внешнего broker state root содержит отдельный AES-GCM vault и writer lock. Новые продукты и provider checkpoints не записываются в старые Meta/YouTube vault. Ключ, процессный single-writer lock, CAS, fsync, atomic rename и отказ после неопределённого commit переиспользуются из StudentVault. Backup должен включать этот подкаталог; checkpoint URLs и credentials секретны. Не копируйте vault в staging.

`social_connections_catalog/list/begin/disconnect` обслуживают подключения. `social_publish_context/submit/status/resume/cancel` используют существующий signed subject transport. Submit связывает tenant, subject, deliveryId, intentId, intentHash, targetHash и connectionId. Канонический JSON и SHA-256 проверяются по `tests/fixtures/publishing-hash-fixture.json`. Lease URL/expiry не входят в content identity. Повтор deliveryId с иным payload отвергается; две доставки одного batch не конфликтуют. Submit возвращает durable acceptance, не обещание успеха.

Runner обрабатывает не более двух доставок одновременно, по одному ограниченному шагу на tick. Повторный шаг назначается через минуту для Instagram и через 15 секунд для остальных площадок; processing ограничен 24 часами, затем требуется явная сверка через resume известной операции. До внешней мутации сохраняется checkpoint с `inFlight`; transport не повторяет запросы автоматически. HTTP provider запрос ограничен 20 секундами, получение исходника — 120 секундами. Видео потоково сохраняется во временный приватный spool и полностью проверяется по SHA/size до мутации; JSON/base64 видео не используется. Временные файлы удаляются после шага, оставшиеся после остановки — при следующем открытии publishing vault. Исходники платформы не удаляются. Сохраняются до 10000 доставок, весь vault ограничен существующим лимитом 20 MB: дальнейшая retention/архивация требует отдельного регламента.

Instagram: container → status → publish → ID/owner/Reels readback. YouTube: resumable session → status probe → upload chunks → processing/owner/privacy/madeForKids readback; отдельная выбранная обложка отправляется в thumbnails.set для известного video ID. TikTok: fresh creator info/privacy/interactions → explicit consent/disclosures → FILE_UPLOAD init/chunks → known publish_id status. Private TikTok не выдаёт публичный post ID: успешная квитанция содержит известный publish_id, без выдуманной permalink. Публичные int64 post IDs сохраняются без округления. Pinterest: media registration → потоковый multipart S3 upload → media status → pin на выбранной доступной доске → ID/board readback. Отдельная обложка необязательна: используется `cover_image_key_frame_time` (по умолчанию 0 секунд).

TikTok требует `isAigc`, оба brand toggles, consent и явное подтверждение коммерческого disclosure с текущим `disclosureVersion`, когда выбран commercial toggle. `brandContentToggle` запрещён вместе с `SELF_ONLY`; только продвижение собственного бренда этого ограничения не включает. Состояние приложения и аудит TikTok оператор проверяет отдельно. Встроенное приложение не подставляет публичную видимость автоматически.

## Восстановление и пределы доказательств

Status никогда не повторяет мутацию. Resume требует expectedVersion, при необходимости принимает новые asset/cover leases только с прежними id/SHA/size/mime. Для доказанного отказа до мутации допустим явный retry. Неизвестный publish не создаётся заново: известная YouTube session сначала опрашивается, TikTok publish_id и Pinterest media_id сверяются. Потерянный ответ создания Instagram container/TikTok init/YouTube session или публикации Instagram/Pinterest без recoverable ID требует ручной сверки; новый post автоматически не создаётся. Cancel прекращает только будущие локальные шаги, не удаляет внешние объекты и не допускается во время выполняющегося шага, после получения ID созданной публикации или после полной передачи TikTok-видео, которое провайдер уже может опубликовать самостоятельно.

Проверки: `npm run typecheck`, `npm test`, `npm run build`; затем `npx vitest run --config tests/student-publishing.compiled.config.mjs` повторяет те же поведенческие fixtures через собранные модули и настоящий HTTP/MCP transport. Адресные tests/student-publishing* покрывают flow четырёх площадок, restart/unknown, смену payload, cross-owner, обновление lease, запрет redirects/corrupt streams, scope upgrade и совместимость прежнего MCP. UI-приёмка и реальные публикации этими тестами не подтверждаются; UI проверяется на staging с вымышленными аккаунтами. Автоматическое тестирование production UI и реальные посты не выполнялись.

## Первичные схемы (проверены 2026-11-11)

- [Pinterest OpenAPI 5.28.0](https://github.com/pinterest/api-description/blob/main/v5/openapi.yaml): Account.id, OauthAccessToken, MediaUpload/MediaResponse, PinMediaSourceVideoID.
- [TikTok Direct Post](https://developers.tiktok.com/docs/en/content-posting-api-reference-direct-post), [creator info](https://developers.tiktok.com/docs/en/content-posting-api-reference-query-creator-info), [status](https://developers.tiktok.com/docs/en/content-posting-api-reference-get-video-status), [UX/disclosures](https://developers.tiktok.com/docs/en/content-sharing-guidelines), [OAuth token lifecycle](https://developers.tiktok.com/docs/en/oauth-user-access-token-management).
- [YouTube resumable upload](https://developers.google.com/youtube/data/guides/using_resumable_upload_protocol), [video readback](https://developers.google.com/youtube/data/reference/rest/v3/videos/list).
- [Instagram content publishing](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/content-publishing/): content-publishing protocol; доступ к приложению проверяется отдельно. В этом проходе web-fetch этой страницы был недоступен; опубликованная [коллекция Meta в Postman](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api) подтверждает container/status/publish последовательность в поисковом индексе. Полное чтение страницы Meta и живой допуск остаются отдельной проверкой.
